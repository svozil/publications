\section{Scope of This Supplement}

This supplement records the computational artifacts used for the projector-cone
and vector-generated closure tables in the paper.  It is designed to make clear
which entries are exact-certified and which entries are numerical
rationalizations.

The accompanying archive contains:
\begin{itemize}
\item \texttt{simplex\_ultimate\_audit.py}, the driver that writes all result
manifests and optionally reruns the numerical and exact audits;
\item \texttt{simplex\_projector\_cone\_vector\_audit.py}, the projector-cone
audit with rational primal and dual certificate checks;
\item \texttt{simplex\_operational\_closure\_vector\_audit.py}, the
vector-generated closure audit;
\item \path{simplex_original_formalism_exact_cdd_v10_completed_audit.py}, the
earlier exact-audit script retained for provenance;
\item JSON manifests and logs produced by the ultimate driver, especially
\begin{itemize}
\item \path{projector_cone_audit_run.json},
\item \path{operational_closure_audit_run.json},
\item \path{exact_certificate_generation_status.json}.
\end{itemize}
\end{itemize}

Exact regeneration of rational facets and exact certificates requires a
fraction/GMP-enabled \texttt{pycddlib}/cddlib installation.  A float-only
\texttt{pycddlib} installation can reproduce numerical LP summaries, but those
runs are not exact certificates.

\section{Certificate Format}

Let
\[
        M_0=I_E^TGI_\Omega,\qquad
        M_1=I_E^TG(D-\operatorname{Id})I_\Omega ,
\]
and let \(C_{\ell k}=(h^E_\ell)^T h^\Omega_k\).  The primal certificate for a
candidate value \(r_*\) is a rational nonnegative matrix \(\sigma\) satisfying
\[
        \sum_{\ell,k}\sigma_{\ell k}C_{\ell k}-r_*M_1=M_0.
\]
The dual certificate is a rational matrix \(Y\) satisfying
\[
        \langle Y,C_{\ell k}\rangle\le 0\quad\text{for all }\ell,k,
        \qquad
        -\langle Y,M_1\rangle\le1,
\]
and
\[
        \langle Y,M_0\rangle=r_* .
\]
Together, these identities certify that \(r_*\) is the exact optimum for the
lower-bounded LP.  Since all certified rows satisfy \(0\le r_*\le1\), the same
certificate applies to the implemented LP with the additional bound \(r\le1\).

The generated \texttt{supplement\_run/exact\_projector\_certificates/}
directory contains one JSON certificate file per exact projector-cone row.
Each file contains
\[
I_\Omega,\ I_E,\ D,\ H_\Omega,\ H_E,\ M_0,\ M_1,\ r_*,\ \sigma,\ Y,
\]
with rational entries serialized as strings.

\section{Program Commands}

The light manifest run is:
\begin{verbatim}
python simplex_ultimate_audit.py --outdir supplement_run
\end{verbatim}
This writes all table entries, certificate-status manifests, dependency
reports, and program hashes.

The full numerical regeneration run is:
\begin{verbatim}
python simplex_ultimate_audit.py --outdir supplement_run --run-full
\end{verbatim}
If the local \texttt{pycddlib} build is float-only, append
\texttt{--allow-float-cdd}.  Those runs are numerical only.

The exact-certificate run is:
\begin{verbatim}
python simplex_ultimate_audit.py --outdir supplement_run ^
  --run-full --save-exact-certificates
\end{verbatim}
and requires exact fraction/GMP cddlib support.

The overnight run of these three commands produced the files in
\path{supplement_run/}.  The projector-cone audit confirms exact rational
primal and dual certificates for all six rational projector-cone rows.  The
closure audit reproduces the closure values with exact cddlib facets, but its
JSON status fields record \texttt{--certify not requested} for the primal
closure rows and ``dual numerical solve has no primal sigma certificate'' for
the Tkadlec cutting-dual rows.  Hence the overnight run changes no table value
and does not upgrade any closure row to exact-certified status.

\section{Input Coordinates}

The rational ray coordinates are stored directly in
\path{simplex_projector_cone_vector_audit.py} under these names:
\[
\texttt{fireflyL12},\quad
\texttt{yuOh13},\quad
\texttt{yuOh25},\quad
\texttt{tkadlecFig2Nonunital},\quad
\texttt{cabello18},\quad
\texttt{peresMermin24}.
\]
The Yu--Oh 25 list is generated from the Yu--Oh 13 list by adding the primitive
cross-product completion of every orthogonal pair.  The algebraic pentagon
branch is generated by \path{kcbs_completed_pentagon_rays_float()}.

\section{Numerical Status}

The projector-cone rows marked ``exact optimum'' have both rational primal
feasibility and rational dual optimality certificates.  These are serialized in
the \texttt{exact\_projector\_certificates/} directory of the run output.  The completed pentagon,
Specker bug, and \(\Gamma_3\) rows remain numerical evidence in the present
archive.  All vector-closure rows remain numerical in the overnight run:
the rational closure facets were exact, but exact primal--dual closure
certificates were not produced.
